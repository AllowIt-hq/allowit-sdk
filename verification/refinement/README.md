# Extracted kernel refinement

The unchanged published `policy.rs` and `policy_api.rs` were extracted through Charon and Aeneas. Lean checks equality with a byte-identical copy of the independently reviewed `NativeDaily` specification for **every** boolean/u64 input. The equality includes termination, all six ordered policy errors and the exact successful spend. A separate theorem connects success to `validRequest`; the existing exact-limit success witness checks nonvacuity.

[Refinement.lean](lean/Refinement.lean) is the handwritten bridge and proof. [AllowitKernel.lean](lean/AllowitKernel.lean) is generated, not transcribed. [The LLBC](kernel/allowit_kernel.llbc), [translation inventory](lean/translation.json), [lock](lock.json), [axiom log](proof-check.txt) and [receipt](receipt.json) bind this result. The checker regenerates LLBC and Lean in a fresh directory and compares their bytes before compiling those generated bytes and frozen specification/proof snapshots in the fresh directory. No production implementation changed.

## Scope and trust

This is **conditional source-linked extracted-model refinement**, not a verified Rust compiler or universal compiled-contract refinement. Rustc, Charon's MIR/LLBC extraction, Aeneas's executable translator and its Rust primitive mapping are trusted to preserve source semantics. The extracted functions call Aeneas models of unsigned division, checked addition, `Option::ok_or`, `Result::branch` and error conversion. The proof uses the library's checked arithmetic lemmas and explicitly bounds every u64 conversion. Their correspondence with Rust is a translation assumption, not a theorem checked here.

The proof checker trusts the official Lean toolchain and cached upstream Lean libraries. Package source revisions, cached olean/native-plugin identities and every file in the Lean/Rust toolchain `lib/` directories are checked before and after the run; those hashes do not prove the cached artifacts were built faithfully from source. The theorem axiom closure contains only `propext`, `Classical.choice` and `Quot.sound`. Local admission/unsafe/native-decision guards supplement that audit; this is not a hostile-proof sandbox.

The extraction wrapper only declares the unchanged two modules in a dependency-free `no_std` crate. The `stellar` feature is disabled. Soroban derives, platform ABI decoding, authorization, storage, transfers, rollback, tuning/upgrades, gateway/client behavior, compiled SBF/Wasm provenance and deployed identity are outside this theorem. API-derived formatting/equality helpers are extracted but are not a verified public API inventory. Charon uses the distributed Rust sysroot (`--sysroot default`), with standard-library primitives supplied by the backend models; no Miri execution or Miri safety result is claimed.

The original Lean 4.11 files, source snapshots, 2,907-case receipts and nine-mutation experiment remain unchanged. The copy of `NativeDaily` keeps its historical source header and checks separately under Lean 4.31. No previous receipt is retargeted. All 24 release obligations remain open; this supplies partial V04/V23 evidence for the pure kernel.

## Run

From the dedicated verification worktree:

```sh
python3 verification/refinement/check.py --tools /tmp/allowit-extraction-oct05
PYTHONPYCACHEPREFIX=/tmp/allowit-proof-python-cache python3 -m unittest discover -s verification/tests -v
```

The tool root is an isolated local cache. The checker needs its pinned `aeneas/` source clone, `release/aeneas`, `aeneas/charon/charon/target/release/{charon,charon-driver}`, `rustup/`, `cargo/` and `lean-4.31.0-darwin_aarch64/`. Lake packages live only under this package's ignored `.lake/`; other caches use the tool root. Source or proof changes, translator changes, unknown extraction, missing artifacts or unexpected axioms fail acceptance. It neither installs tools nor downloads missing dependencies during acceptance; Cargo is explicitly offline. Default acceptance also compares the retained receipt with the current lock and checked result. To produce a newly reviewed candidate, use `--emit-receipt` and explicitly refresh its ledger bindings.

To prepare a new environment, use the upstream [build instructions at the exact Aeneas pin](https://github.com/AeneasVerif/aeneas/blob/557eff83ecef5083b98a52a94ca7fae63d6c1dab/README.md) and [Charon toolchain file](https://github.com/AeneasVerif/charon/blob/c8f15d7d658c86a95658f71ad99cddd4be002e04/rust-toolchain). Set `RUSTUP_HOME`, `CARGO_HOME` and `XDG_CACHE_HOME` to isolated directories before setup. Build Charon with `cargo build --locked --release --bin charon --bin charon-driver`; install the pinned nightly's `rustc-dev`, `rust-src` and `llvm-tools`. On macOS, direct invocation also requires its sysroot `lib/` on `DYLD_LIBRARY_PATH`. The Aeneas macOS release avoids a global OCaml/OPAM installation.

Use the separate pinned Lake package and official matching Aeneas backend cache. Fetch only the Mathlib module closure imported by `Aeneas/` (about 1,400 modules at this pin), then build `AllowitKernel` and `NativeDaily`. A full Mathlib cache is unnecessary. Check available disk before bootstrap; this environment uses several GiB. Never update the old Lean 4.11 package to satisfy this dependency.

## Extension boundary

First extend the independent state specification, then prove the delivered adapter's authenticated context and state effects against it. SDK/gateway/CLI/frontend inventories and traces provide separate obligations once those handoffs arrive. A new ABI or changed compiler/translator/source/configuration invalidates its affected bindings. Semantic classification stays outside deterministic kernel arithmetic: customer-bound Jev evidence, configured decision thresholds and separate calibration obligations remain explicit.

Independent [Opus 5.5 closure review](https://github.com/ackrate/ackrate-project/blob/main/instance/artifacts/107-allowit-repository-artifacts/AllowIt-sdk/revisions/1da2738d3dc5d544829d9e012533b007e0ceafcc/docs/reviews/2026-10-04-kernel-refinement.md) reproduced the retained receipt and passed all 18 tests after acceptance-check repairs; no remaining material findings were reported.
